<!-- sdlc:auto:start overview -->
To-do-app is a simple to-do web app generated by the Quorq AI SDLC platform. Users sign up, log in, and manage their own tasks. The repository holds two applications. `frontend/` is a Vite + React 19 single-page app (TypeScript, Tailwind CSS v4, React Router 7) with Login, Signup and Tasks screens. These screens still render seeded sample data; `src/lib/api.ts` (`apiFetch`, session-token helpers) is the place to wire them to the real API. `backend/` is a FastAPI 0.115 service on PostgreSQL 16, using SQLAlchemy 2.0 models (users, sessions, tasks), Pydantic schemas and Alembic migrations. It applies migrations and seeds users on startup. It currently exposes `GET /health`, `POST /auth/signup`, `POST /auth/login` (both return an opaque bearer token in the response body) and `GET /tasks` (the current user's tasks). There are no create, edit or delete task endpoints yet. Deployment is a GitHub Actions workflow that pushes the backend image to AWS ECR and publishes the frontend to AWS Amplify.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Python 3.12 (the backend Dockerfile base image) with pip
- Node.js with npm (no version is pinned in the repo)
- Docker with Docker Compose (for the local PostgreSQL 16 database)
- Chromium for Playwright, installed via `npm run test:e2e:install` (only needed for end-to-end tests)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. docker compose up -d db
2. cd backend
3. python -m venv .venv && . .venv/bin/activate
4. pip install -r requirements.txt
5. export DATABASE_URL='postgresql+psycopg://<db-user>:<database-password>@localhost:<db-port>/<db-name>'  # use the user, password and database from docker-compose.yml
6. uvicorn app.main:app --reload  # applies Alembic migrations and seeds users on startup; health check at /health
7. cd ../frontend  # in a second terminal
8. npm install
9. npm run dev
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one router module per component in app/routers, each registered in main.py with include_router.
- Backend: SQLAlchemy 2.0 typed models (Mapped/mapped_column). Schema changes go only through Alembic migrations, which run on app startup rather than at import.
- Backend: Pydantic request and response models live in app/schemas.py. Emails are trimmed and lowercased, and uniqueness is enforced on lower(email).
- Backend: session tokens are opaque values from secrets.token_urlsafe. Only their sha256 hash is stored, and sessions last 30 days.
- Backend: validation errors return only loc, msg and type, never the submitted input.
- Backend: configuration comes from environment variables: DATABASE_URL (a SQLAlchemy postgresql+psycopg URL) and ALLOWED_ORIGINS (a comma-separated CORS list).
- Backend: Ruff for linting and formatting. bcrypt is pinned to 4.0.x for passlib compatibility.
- Frontend: the `@/` import alias maps to `src/`.
- Frontend: one module per screen in src/screens, with Vitest component tests beside them as *.test.tsx.
- Frontend: styling uses Tailwind with brand CSS variables (var(--brand-*)) from index.css and lib/brand.ts.
- Frontend: API calls go through apiFetch in src/lib/api.ts. It uses VITE_API_BASE_URL (falling back to http://localhost:8000) and sends the session token from localStorage as a Bearer header, falling back to VITE_API_SECRET_KEY.
- Frontend: TypeScript runs in strict mode, but noImplicitAny and strictNullChecks are disabled. ESLint and Prettier are configured, and `npm run lint` is a platform gate.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| The backend crashes on startup with a database connection or authentication error. | Startup runs migrations, so Postgres must be up. Run `docker compose up -d db` and export DATABASE_URL with the user, password and database from docker-compose.yml. The built-in fallback URL has no password. |
| Password hashing raises errors after upgrading packages. | Keep bcrypt pinned at 4.0.1 as in requirements.txt. passlib 1.7.4 is incompatible with bcrypt 5. |
| `npm run test:e2e` cannot start the backend. | The Playwright config runs `.venv/bin/python` inside backend/. Create backend/.venv, install requirements.txt into it, and make sure DATABASE_URL points at a running Postgres. Run `npm run test:e2e:install` first to get Chromium. |
| The browser blocks API calls with CORS errors. | Set ALLOWED_ORIGINS (comma-separated) on the backend to include the frontend's origin, such as the Vite dev server URL. |
| `npm run build` succeeds but deployment or typecheck fails. | Build does not typecheck. Run `npm run typecheck` and fix the reported errors, which are often untyped `useState({})` values. |
| The screens show sample data instead of real tasks. | This is expected: the screens have not been wired to the API yet. Replace the seeded data with apiFetch calls from src/lib/api.ts, and call setSessionToken with the token returned by /auth/login or /auth/signup. |
| `pytest` fails with `ModuleNotFoundError: app`. | Run pytest from the backend/ directory so pytest.ini's `pythonpath = .` applies. |
<!-- sdlc:auto:end troubleshooting -->
